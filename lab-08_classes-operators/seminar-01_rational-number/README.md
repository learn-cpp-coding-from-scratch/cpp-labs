# Задача семинара 1

**Разработайте класс `RationalNumber` — рациональное число в виде несократимой дроби — с арифметическими операциями, сравнением и выводом, и класс `Program` для демонстрации работы с рациональными числами.**

Объявления классов и функций даны в `include/*.hpp`: в комментариях к ним — что делает каждая функция и примеры. После каждого пункта проверяйте себя открытыми тестами и дописывайте свои тесты в `tests/student/`.

### 1. Инвариант и конструктор

1. Класс `RationalNumber` хранит числитель `numerator_` и знаменатель `denominator_` типа `int`. Инвариант класса: знаменатель больше нуля, дробь несократима.
2. Конструктор `RationalNumber(int numerator = 0, int denominator = 1)` служит и конструктором по умолчанию (дробь `0/1`), и неявным преобразованием целого числа в дробь (`n` становится `n/1`). При знаменателе, равном 0, конструктор бросает исключение `std::invalid_argument`.
3. Закрытая функция-член `normalize()` восстанавливает инвариант: переносит знак в числитель и сокращает дробь на наибольший общий делитель (`std::gcd` из `<numeric>`). Конструктор вызывает её после инициализации полей.
4. Константные функции доступа `getNumerator()` и `getDenominator()`.

### 2. Арифметические операции

1. Составные операции `+=`, `-=`, `*=`, `/=` — функции-члены: каждая меняет `*this`, восстанавливает инвариант и возвращает ссылку на `*this`. При делении на нулевую дробь `/=` бросает исключение `std::domain_error`.
2. Бинарные операции `+`, `-`, `*`, `/` — обычные функции (не члены класса), выраженные через составные.
3. Унарный `-` — функция-член.

### 3. Сравнение

1. `operator==` объявлен с `= default`.
2. `operator<=>` — обычная функция с типом результата `std::strong_ordering`: сравнение `a/b` и `c/d` сводится к сравнению `a·d` и `c·b`. Произведения вычисляйте в `long long`.
3. Остальные операции сравнения (`!=`, `<`, `>`, `<=`, `>=`) вручную не пишите — компилятор получает их из `==` и `<=>`.

### 4. Вывод

Операция `<<` — обычная функция, использующая только открытый интерфейс класса (функции доступа). Формат: `числитель/знаменатель`; если знаменатель равен 1 — только числитель.

### 5. Правило нуля

Не пишите в классе ни деструктор, ни копирующий конструктор, ни операцию присваивания. Проверьте, что работают копирование `RationalNumber b = a;` и присваивание целого числа `b = 5;`, и объясните, какие функции для этого создал компилятор и как число `5` становится дробью.

### 6. Класс Program

Весь ввод и вывод — в классе `Program`. Поля `first_` и `second_` типа `RationalNumber`; конструктор не пишите — поля инициализируются конструктором `RationalNumber` по умолчанию.

- `main()` — работа с клавиатурой и консолью: возвращает `run(std::cin, std::cout)`, код возврата — 0, при ошибке ввода — 1. Функция `main` программы только создаёт объект `Program` и возвращает результат его `main()`:

  ```cpp
  int main()
  {
      Program app;
      return app.main();
  }
  ```
- `run(in, out)` — вводит две дроби, выводит их, результаты `+`, `-`, `*`, `/` и шести сравнений. Формат вывода — в комментарии к функции в `program.hpp`. Потоки — параметры, поэтому программу можно проверить тестами, подставив `std::istringstream` и `std::ostringstream`.
- `readRationalNumber()` — ввод дроби; при нулевом знаменателе выводит сообщение `e.what()` и просит ввести дробь заново.
- `printArithmetic()` — арифметика; при делении на ноль выводит сообщение `e.what()` вместо частного.
- `printComparisons()` — сравнения.

### 7. Вопросы

1. Почему для дроби `operator==` можно объявить с `= default`, а `operator<=>` — нельзя? Приведите пару дробей, для которых `operator<=> = default` дал бы неверный результат.
2. Почему составные операции — функции-члены, а бинарные — обычные функции? Что перестанет компилироваться, если сделать `operator+` функцией-членом?
3. Почему `operator<<` нельзя сделать функцией-членом класса `RationalNumber`?
4. Что перестанет компилироваться, если объявить конструктор с `explicit`?
5. Зачем `normalize()` закрыта (`private`)? Что сломается, если пользователь класса сможет менять `numerator_` напрямую?
6. Что произойдёт при вычислении `RationalNumber{2'147'483'647} + 1` и почему? Как можно было бы это исправить?
