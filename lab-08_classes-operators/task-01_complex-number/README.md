# Задача 1

**Разработайте класс `ComplexNumber` — комплексное число — с арифметическими операциями и сравнением на равенство по правилам C++20, выведите в консоль множество Мандельброта и разработайте класс `Program` для демонстрации работы с комплексными числами.**

Объявления классов и функций даны в `include/*.hpp`: в комментариях к ним — что делает каждая функция и примеры. Сравнение на равенство до C++20 (часть 2 лабораторной) — отдельная задача, она собирается с флагом `-std=c++17`; выполните её после части 1.

### Часть 1. Класс ComplexNumber

1. Класс `ComplexNumber` (комплексное число `re + im·i`) хранит действительную и мнимую части в полях `re_` и `im_` типа `double`.
2. Конструктор `ComplexNumber(double re = 0.0, double im = 0.0)` служит и конструктором по умолчанию (число 0), и неявным преобразованием `double` → `ComplexNumber` (число `x` становится `x + 0·i`). Поэтому `explicit` не пишите.
3. Функции доступа `getRe()`, `getIm()` и функции-члены `conjugate()` (сопряжённое число `re − im·i`) и `abs()` (модуль `√(re² + im²)`).
4. Операции `+`, `-`, `*`, `/` для двух комплексных чисел и для комплексного числа и `double` в обоих порядках операндов (`z + 1.0` и `1.0 + z`): составные `+=`, `-=`, `*=`, `/=` — функции-члены, бинарные — обычные функции, выраженные через составные. Унарный `-` и вывод `<<` в виде `(re, im)`. При делении на 0 бросайте исключение `std::invalid_argument`.

### Часть 3. Сравнение на равенство в C++20

1. **Эксперимент (в решение не входит).** Объявите `==` и `!=` функциями-членами, как в пункте 1 задачи о сравнении до C++20, и соберите эту задачу (C++20). Компилируется ли `1.0 == z`? Удалите `operator!=` и проверьте снова. Объясните результат.
2. Оставьте одну функцию-член `operator==`. Проверьте, что компилируются `z == 1.0`, `z != 1.0`, `1.0 == z`, `1.0 != z`. Объясните, как компилятор вычисляет `1.0 == z` и `z != 1.0`.
3. Замените тело `operator==` объявлением `bool operator==(const ComplexNumber&) const = default;` (так он объявлен в `complex_number.hpp`). Почему для комплексного числа сравнение по умолчанию даёт верный результат? Сравните с рациональной дробью: что нужно дроби, чтобы `== default` было верным?
4. Сравните количество функций сравнения в задаче о сравнении до C++20 и в этой.

### Часть 4. Почему у комплексного числа нет `<=>`

1. Попробуйте скомпилировать `z1 < z2` для двух объектов `ComplexNumber`. Объясните результат.
2. Почему для комплексных чисел не определяют операцию `<`? Рассмотрите упорядочение по модулю: какие числа оно считает «эквивалентными», хотя они не равны (например, `1`, `-1`, `i`)? Согласовано ли оно со сложением, как порядок действительных чисел (из `a < b` следует `a + c < b + c`)?
3. Поля `re_` и `im_` имеют тип `double`, поэтому `==` сравнивает их точно. Чему равно `ComplexNumber{0.1 + 0.2} == ComplexNumber{0.3}` и почему? Как сравнить два комплексных числа приближённо? Почему приближённое сравнение оформляют отдельной функцией (например, `isClose(a, b, eps)`), а не операцией `==`?

### Часть 5. Множество Мандельброта в консоли

Множество Мандельброта — это комплексные числа `c`, для которых последовательность `z₀ = 0`, `zₙ₊₁ = zₙ² + c` остаётся ограниченной. Если на каком-то шаге `|zₙ| > 2`, последовательность уходит в бесконечность и `c` множеству не принадлежит.

1. Функция `escapeIterations(c, maxIterations)` возвращает номер шага, на котором модуль `z` впервые стал больше 2, или `maxIterations`, если этого не произошло. Используйте операции класса `ComplexNumber`:

   ```cpp
   ComplexNumber z;
   int n = 0;
   while (n < maxIterations && z.abs() <= 2.0) {
       z = z * z + c;
       ++n;
   }
   ```

2. Функция `shadeFor(iterations, maxIterations)` выбирает символ из массива `SHADES` (символы ` .:-=+*#%@`): `'@'`, если `iterations == maxIterations`, иначе `SHADES[iterations * (SHADES.size() - 1) / maxIterations]`.
3. Функция `renderMandelbrot(area, width, height, maxIterations)` возвращает картинку — `height` строк по `width` символов. Символу в столбце `col` и строке `row` соответствует число `c = re + im·i`, где `re = reMin + (reMax − reMin) · col / width`, `im = imMin + (imMax − imMin) · row / height`. Вся картинка — `DEFAULT_AREA` (`re` от −2,2 до 0,8, `im` от −1,2 до 1,2) при 70 × 24 символах. Символ консоли примерно вдвое выше своей ширины, поэтому шаг по `re` (3,0 / 70) взят меньше шага по `im` (2,4 / 24) — иначе картинка вытянется по вертикали.
4. Поменяйте границы, чтобы увеличить фрагмент границы множества, например `re` от −0,8 до −0,7 и `im` от 0,05 до 0,15. Что приходится сделать с `maxIterations`, чтобы детали не пропадали, и почему?
5. Почему горизонтальная строка посередине картинки (`im = 0`) от `re = -2` до `re = 0.25` целиком состоит из символов `'@'`?

### Часть 6. Класс Program

Весь ввод и вывод — в классе `Program`, класс `ComplexNumber` с клавиатурой не работает.

- `main()` — работа с клавиатурой и консолью: возвращает `run(std::cin, std::cout)`, код возврата — 0, при ошибке ввода — 1. Функция `main` программы только создаёт объект `Program` и возвращает результат его `main()`:

  ```cpp
  int main()
  {
      Program app;
      return app.main();
  }
  ```
- `run(in, out)` выводит меню и выполняет выбранный пункт, пока пользователь не выберет выход: `1` — арифметика (`printArithmetic`), `2` — множество Мандельброта (`printMandelbrot`), `0` — выход. Формат вывода — в комментариях к функциям в `program.hpp`. Потоки — параметры, поэтому программу можно проверить тестами.
- `readComplexNumber()` — ввод действительной и мнимой частей.
- `printArithmetic()` — вводит два числа и выводит результаты `+`, `-`, `*`, `/`, сопряжённое число, модули и результат сравнения `==`; при делении на ноль выводит сообщение `e.what()` вместо частного.
- `printMandelbrot()` — вводит границы и `maxIterations` и выводит множество Мандельброта.
