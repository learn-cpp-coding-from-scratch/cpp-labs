# Задача 1

**Разработайте шаблон класса `Matrix<T>` — прямоугольная матрица в динамической памяти — с правилом пяти, операциями над матрицами, вводом и выводом, и класс `MatrixService` с транспонированием, поворотом, определителем, обратной матрицей и решением уравнения `AX = B`.**

Объявления даны в `include/matrix.hpp` и `include/matrix_service.hpp`: в комментариях к ним — что делает каждая функция и примеры. Определения шаблонов пишите в тех же файлах ниже классов, операции-друзья — внутри класса; обычные функции `MatrixService` — в `src/matrix_service.cpp`. После каждого пункта проверяйте себя открытыми тестами и дописывайте свои тесты в `tests/student/`.

### 1. Поля и правило пяти

1. Поля: `rows_`, `columns_` (тип `std::size_t`) и `data_` (тип `T**`) — массив из `rows_` указателей на строки, каждая строка — массив из `columns_` элементов. Инвариант: у пустой матрицы `rows_ == columns_ == 0` и `data_ == nullptr`, у непустой оба размера больше нуля.
2. Закрытые статические функции `allocate(rows, columns)` и `release(data, rows)` выделяют и освобождают память матрицы. Если в `allocate` выделение очередной строки бросило исключение, уже выделенные строки освобождаются, а исключение передаётся дальше.
3. Конструкторы:
   - `Matrix()` — пустая матрица 0×0;
   - `Matrix(rows, columns)` — элементы `T{}`;
   - `Matrix(rows, columns, value)` — элементы `value`;
   - `Matrix(std::initializer_list<std::initializer_list<T>> rows)` — `Matrix<int> m{{1, 2}, {3, 4}}`; строки разной длины или пустые — исключение `std::invalid_argument`.

   Нулевое число строк или столбцов в конструкторах с размерами — исключение `std::invalid_argument`.
4. Единичная и диагональная матрицы — именованные конструкторы, статические функции-члены: `Matrix<T>::identity(n)` и `Matrix<T>::diagonal({d1, d2, …})`.
5. Правило пяти: деструктор, конструктор копирования (глубокое копирование), конструктор перемещения (`noexcept`, исходная матрица становится пустой), присваивание `operator=(Matrix other) noexcept` по идиоме копирования и обмена.

### 2. Доступ к элементам

1. `rows()`, `columns()` и `m(i, j)` — элемент без проверки индексов (операция вызова функции) — уже написаны.
2. `at(i, j)` — с проверкой: выход за границы — исключение `std::out_of_range`.

### 3. Операции

| Операция | Что делает |
|---|---|
| `a += b`, `a -= b`, `a + b`, `a - b` | сложение и вычитание матриц; при разных размерах — исключение `std::invalid_argument` |
| `a *= x`, `a * x`, `x * a` | умножение на значение `x` типа `T` |
| `a /= x`, `a / x` | деление на `x`; при `x == T{}` — исключение `std::domain_error` |
| `a * b` | произведение матриц; если число столбцов `a` не равно числу строк `b` — исключение `std::invalid_argument` |
| `-a` | противоположная матрица |
| `a == b` | равны размеры и все элементы; `!=` получает компилятор |
| `out << m` | каждая строка матрицы — на отдельной строке, элементы через пробел: `1 2\n3 4\n`; пустая матрица ничего не выводит |
| `in >> m` | число строк, число столбцов, затем элементы по строкам: `2 2 1 2 3 4`; `0 0` — пустая матрица; при ошибке ввода — `failbit`, матрица не меняется |

### 4. Класс MatrixService

Статические функции-члены:
- шаблоны `add(a, b)`, `subtract(a, b)`, `multiply(a, b)` (произведение матриц), `multiply(a, x)` — аналоги операций;
- шаблон `transpose(m)` — транспонированная матрица;
- шаблон `rotate(m, degrees)` — поворот на угол, кратный 90° (90, 180, 270, −90, −180, −270, а также 0, 360 и т. д.); положительный угол — против часовой стрелки: `rotate({{1, 2}, {3, 4}}, 90)` даёт `{{2, 4}, {1, 3}}`; угол, не кратный 90, — исключение `std::invalid_argument`;
- обычные функции для `Matrix<double>` (в `src/matrix_service.cpp`), методом Гаусса с выбором главного элемента в столбце:
  - `determinant(a)` — определитель;
  - `inverse(a)` — обратная матрица;
  - `solve(a, b)` — решение матричного уравнения `AX = B` (`a` — n×n, `b` — n×k, результат — n×k).

  Пустая или неквадратная матрица `a`, несогласованные размеры `a` и `b` — исключение `std::invalid_argument`. Главный элемент, по модулю меньший `1e-9` (`cpplabs::DEFAULT_EPSILON` из `<cpplabs/numbers.hpp>`), считается нулём: определитель такой матрицы равен 0, а `inverse` и `solve` бросают исключение `std::domain_error`.

### 5. Тесты

Примеры, которые проверяют открытые тесты:

| Выражение | Ожидаемый результат |
|---|---|
| `Matrix<int>::identity(2)` | `{{1, 0}, {0, 1}}` |
| `Matrix<int>{{1, 2}, {3}}` | исключение `std::invalid_argument` |
| `Matrix<int>{{1, 2}, {3, 4}} * Matrix<int>{{5}, {6}}` | `{{17}, {39}}` |
| `MatrixService::transpose(Matrix<int>{{1, 2, 3}})` | `{{1}, {2}, {3}}` |
| `MatrixService::rotate(m, 360)` | `m` |
| `MatrixService::determinant(Matrix<double>{{1, 2}, {3, 4}})` | `-2` |
| `MatrixService::inverse(a) * a` | единичная матрица (с точностью `1e-9`) |
| `MatrixService::inverse(Matrix<double>{{1, 2}, {2, 4}})` | исключение `std::domain_error` |

### 6. Вопросы

1. Почему в `allocate` нельзя просто выделить строки в цикле без обработки исключения? Что произойдёт, если `new` бросит `std::bad_alloc` на третьей строке?
2. Чем хранение `T**` хуже одного блока `T*` из `rows_ * columns_` элементов? Как в этом случае вычисляется положение элемента `(i, j)`?
3. Почему `determinant`, `inverse`, `solve` объявлены для `Matrix<double>`, а не для любого `Matrix<T>`? Что получилось бы для `Matrix<int>`?
4. Почему `identity` и `diagonal` — статические функции, а не конструкторы?
5. Почему для `Matrix<double> m` вызов `MatrixService::multiply(m, 2)` не компилируется, а `m * 2` компилируется?
6. Можно ли было хранить матрицу как `Array<Array<T>>` из задачи семинара? Какие функции правила пяти тогда пришлось бы написать?
