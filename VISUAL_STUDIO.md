# Windows и Visual Studio

Эта заметка — для тех, кто работает в Windows и хочет выполнять лабораторные в среде разработки **Visual Studio** (Community 2022 или 2026), а не в VS Code. Основные инструкции курса написаны для VS Code; здесь описано, чем работа в Visual Studio отличается: установка (вместо раздела 1 [SETUP.md](SETUP.md)), открытие проекта, сборка, запуск, тесты, отладка и Git. Всё остальное — как у всех: регистрация на GitHub и своя копия репозитория — [SETUP.md](SETUP.md), разделы 4 и 5; получение и сдача лабораторных — [WORKFLOW.md](WORKFLOW.md); как устроены задачи — [README.md](README.md).

**Visual Studio и VS Code — разные программы.** Visual Studio — большая среда разработки Microsoft со своим компилятором **MSVC**; VS Code — редактор, который курс использует на всех системах. Проект курса описан для **CMake**, а Visual Studio умеет открывать проекты CMake напрямую, без файлов решения `.sln`: она читает `CMakeLists.txt` и пресеты из `CMakePresets.json`. Поэтому создавать в Visual Studio новый проект не нужно — открывается папка репозитория.

## 1. Установка

1. Скачайте **Visual Studio Community** (бесплатная) со страницы https://visualstudio.microsoft.com или установите командой в PowerShell:
   ```powershell
   winget install Microsoft.VisualStudio.2022.Community
   ```
2. В окне **Visual Studio Installer** на вкладке **Workloads** (**Рабочие нагрузки**) отметьте **Desktop development with C++** (**Разработка классических приложений на C++**). В правой колонке **Installation details** (**Сведения об установке**) проверьте, что отмечены:

   | Компонент | Что внутри |
   |---|---|
   | **MSVC … C++ x64/x86 build tools** (отмечен по умолчанию) | компилятор MSVC (`cl`) |
   | **C++ CMake tools for Windows** (**Инструменты CMake C++ для Windows**, отмечен по умолчанию) | CMake и Ninja |
   | **C++ Clang tools for Windows** (**Инструменты C++ Clang для Windows**) — **отметьте сами** | clang-tidy и clang-format — проверка и форматирование кода по стилю курса |

   Нажмите **Install** (**Установить**). Установка занимает 10–30 минут и несколько гигабайт на диске.

   Если Visual Studio уже установлена: запустите **Visual Studio Installer** из меню «Пуск» → **Modify** (**Изменить**) и добавьте недостающее. Там же — **Update** (**Обновить**): проекту нужен CMake 3.24 или новее, он входит в Visual Studio 2022 версии 17.4 и новее.
3. В **PowerShell** установите Git и GitHub CLI — с ними работают команды из [SETUP.md](SETUP.md) и [WORKFLOW.md](WORKFLOW.md):
   ```powershell
   winget install Git.Git GitHub.cli
   ```
   Закройте и снова откройте PowerShell, чтобы команды `git` и `gh` стали доступны.

**MSYS2 и VS Code из раздела 1 [SETUP.md](SETUP.md) устанавливать не нужно.** Если они уже установлены — не мешают: Visual Studio использует свой компилятор и свои CMake и Ninja.

Дальше выполните разделы 4 и 5 [SETUP.md](SETUP.md) (Git, вход в GitHub, своя копия репозитория) в PowerShell, с одним отличием: строку
```sh
git config --global core.editor "code --wait"
```
выполняйте, только если VS Code у вас всё же установлен. Без неё Git в редких случаях (например, `git commit` без `-m`) откроет консольный редактор vim прямо в терминале: чтобы сохранить и выйти, наберите `:wq` и нажмите Enter.

## 2. Открыть проект и выбрать пресет

1. Запустите Visual Studio. В стартовом окне выберите **Open a local folder** (**Открыть локальную папку**) или в меню **File → Open → Folder…** (**Файл → Открыть → Папка…**) и выберите **корневую папку репозитория** `cpp-labs` — ту, где лежит `CMakePresets.json`. Не папку лабораторной и не папку задачи: весь репозиторий — один проект.

   Не используйте **Create a new project** и **Open a project or solution**: файлов `.sln` в курсе нет. Если Visual Studio предложит создать файл `CMakeSettings.json` — откажитесь: настройки уже есть в `CMakePresets.json`.
2. **Выберите пресет.** На панели инструментов вверху окна появится список **Configuration** (**Конфигурация**) — в нём пресеты из `CMakePresets.json`. Выберите **Debug (MSVC)**.

   В списке есть и другие пресеты — **Debug (GCC/Clang)** и **Debug (Clang, модули C++20)**: они для g++ из MSYS2 и Clang, которых в этом варианте нет, — не выбирайте их.
3. Visual Studio сама запустит настройку CMake. Ход настройки виден в окне **Output** (**Вывод**; меню **View → Output**, `Ctrl+Alt+O`), в списке **Show output from** — **CMake**. При первой настройке CMake скачивает библиотеки Google Test, Catch2 и spdlog — нужен интернет. Настройка закончена, когда появилась строка `CMake generation finished` (или `Generating done`).

   Посмотрите в этом выводе, нет ли строки `clang-tidy не найден — сборка без проверки стиля` — если есть, см. раздел 5.

Папка сборки — `build\msvc-debug`, программы и тесты собираются в `build\msvc-debug\bin`. Папки `build\` и `.vs\` (её создаёт Visual Studio) в Git не попадают: они перечислены в `.gitignore`.

**Обозреватель решений** (**Solution Explorer**, `Ctrl+Alt+L`) показывает папку репозитория как дерево файлов (**Folder View**). Кнопка **Switch between solutions and available views** (**Переключение между решениями и доступными представлениями**) вверху обозревателя переключает его на **CMake Targets View** — список целей сборки: программ и тестов всех задач.

## 3. Сборка, запуск и отладка

Имена целей те же, что в [README.md](README.md): программа — `lab-NN-task-NN_<задача>`, открытые тесты — `lab-NN-task-NN-tests`, ваши тесты — `lab-NN-task-NN-tests-student`. Имя программы указано в `README.md` задачи. Пример — задача 2 лабораторной 1.

1. **Откройте условие и код задачи** в обозревателе решений: `lab-01_linear-algorithms\task-02_arithmetic\README.md` и `src\arithmetic.cpp`. Файл `.md` Visual Studio показывает оформленным в режиме предпросмотра (кнопка **Preview** вверху вкладки), его удобно читать и на GitHub.
2. **Выберите программу для запуска:** на панели инструментов, рядом с зелёной стрелкой ▶, — список **Select Startup Item** (**Выбрать элемент запуска**). Выберите `lab-01-task-02_arithmetic.exe`. Другой способ — в **CMake Targets View** правый щелчок по цели → **Set as Startup Item** (**Назначить элементом запуска**).
3. **Соберите:** **Build → Build All** (**Сборка → Собрать всё**), `Ctrl+Shift+B` или `F7`. Собираются все программы и тесты всех задач, при этом clang-tidy проверяет стиль. Ошибки и предупреждения — в окне **Error List** (**Список ошибок**; **View → Error List**, `Ctrl+\, E`), полный текст — в окне **Output**, в списке **Show output from** — **Build**. Двойной щелчок по сообщению открывает строку с ошибкой. Пока функции не написаны, компилятор предупреждает о неиспользуемых параметрах (`unreferenced parameter`, `C4100`) — это ожидаемо.
4. **Запустите без отладки:** **Debug → Start Without Debugging** (**Отладка → Запуск без отладки**), `Ctrl+F5`. Программа откроется в отдельном окне консоли — туда вводите данные и нажимайте Enter. После завершения программы окно ждёт нажатия клавиши (`Press any key to close this window`), чтобы вы успели прочитать вывод.

   Пока функции не написаны, программа остановится на первой проверке. MSVC сообщает о ней так:
   ```
   Assertion failed: sum(7, 2) == 9, file …\arithmetic.cpp, line 16
   ```
   В отладочной сборке Windows вдобавок может показать окно **Microsoft Visual C++ Runtime Library** с кнопками **Abort**, **Retry**, **Ignore**: **Abort** завершает программу, **Retry** открывает отладчик на этой строке. Это ожидаемо — напишите решение вместо заглушки `return {};` и повторите шаги 3–4.
5. **Отладка:** поставьте точку останова — щёлкните на полях слева от номера строки (появится красная точка) или `F9` — и нажмите **F5** (**Debug → Start Debugging**). Программа остановится на этой строке; значения переменных — в окнах **Autos** и **Locals** (**Видимые** и **Локальные**) внизу, **F10** — выполнить строку, **F11** — войти в функцию, **Shift+F11** — выйти из функции, **F5** — продолжить, **Shift+F5** — остановить.

   При запуске с отладкой (F5) окно консоли по умолчанию закрывается сразу после завершения программы. Чтобы оно оставалось открытым: **Tools → Options → Debugging → General** (**Сервис → Параметры → Отладка → Общие**) → снимите флажок **Automatically close the console when debugging stops** (**Автоматически закрыть консоль при остановке отладки**).

**Переход к другой задаче.** Открыть файл другой задачи недостаточно: ▶ и `Ctrl+F5` запускают программу, выбранную в **Select Startup Item**. Выберите там программу новой задачи (в списке можно начать вводить имя, например `task-05`) и снова соберите и запустите.

Пересобирать проект целиком после каждой правки не нужно: `Ctrl+F5` и F5 сами собирают выбранную программу, если её файлы изменились. Но **Build All** собирает и тесты, и проверяет стиль во всех изменённых файлах — выполняйте её перед коммитом.

## 4. Тесты (с лабораторной 3)

1. **Соберите** проект: `Ctrl+Shift+B` — собираются и программы, и тесты.
2. Откройте **Test → Test Explorer** (**Тест → Обозреватель тестов**, `Ctrl+E, T`). Visual Studio находит тесты через CTest: в списке появятся тесты всех задач с именами `lab-03-task-04.open.<Набор>.<Тест>` (открытые) и `lab-03-task-04.student.<Набор>.<Тест>` (ваши, на Google Test или Catch2). Если список пуст — соберите проект ещё раз; если не помогло — **Project → Delete Cache and Reconfigure** (**Проект → Удалить кэш и перенастроить**), затем снова сборка.
3. **Запустите:** **Run All Tests** (**Выполнить все тесты**, `Ctrl+R, A`) или правый щелчок по тесту либо группе → **Run** (**Выполнить**). Чтобы найти тесты одной задачи, введите её префикс, например `lab-03-task-04`, в поле поиска обозревателя тестов. Непройденные тесты отмечены красным; щелчок по тесту показывает внизу, какая проверка не прошла и с какими значениями. Пока функции не написаны, тесты не проходят — это ожидаемо.
4. **Отладка теста:** поставьте точку останова в тесте или в функции из `src\<задача>.cpp`, выберите в **Select Startup Item** цель с тестами — `lab-03-task-04-tests.exe`, `lab-03-task-04-tests-student.exe` или `lab-03-task-04-tests-student-catch2.exe` — и нажмите **F5**. Выполнятся все тесты этой цели, а программа остановится на точке останова. Можно и из обозревателя тестов: правый щелчок по тесту → **Debug** (**Отладка**).

Как писать свои тесты в `tests/student/` — в [README.md](README.md), раздел «Лабораторные с Google Test или Catch2». Новый файл с тестами подхватывается при следующей сборке.

## 5. Стиль кода: clang-tidy и clang-format

**clang-tidy** проверяет стиль при каждой сборке (раздел 3, шаг 3): его замечания — в окне **Error List** вместе с ошибками компилятора, в квадратных скобках — название проверки, например `[readability-magic-numbers]`. Замечания нужно исправить, как и в VS Code.

Если при настройке CMake в окне **Output** появилась строка `clang-tidy не найден — сборка без проверки стиля`, значит, CMake не нашёл программу `clang-tidy`:
1. Проверьте, что в Visual Studio Installer отмечен компонент **C++ Clang tools for Windows** (раздел 1).
2. Добавьте папку с clang-tidy в переменную среды `Path` — так же, как в пункте 3 раздела «Windows» [SETUP.md](SETUP.md), — `C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\Llvm\x64\bin` (для Visual Studio 2026 вместо `2022` — номер версии в имени папки; проверьте путь в Проводнике).
3. Закройте Visual Studio, откройте снова и выполните **Project → Delete Cache and Reconfigure** (**Проект → Удалить кэш и перенастроить**).

**clang-format.** Visual Studio сама находит файл `.clang-format` в корне репозитория и форматирует код по нему. Отформатировать открытый файл: **Edit → Advanced → Format Document** (**Правка → Дополнительно → Форматировать документ**), `Ctrl+K, Ctrl+D`. Делайте это перед каждым коммитом. Проверьте, что поддержка clang-format включена: **Tools → Options → Text Editor → C/C++ → Code Style → Formatting → General** (**Сервис → Параметры → Текстовый редактор → C/C++ → Стиль кода → Форматирование → Общие**) → флажок **Enable ClangFormat support** (**Включить поддержку ClangFormat**).

Форматировать файл автоматически при каждом сохранении, как в VS Code: **Tools → Options → Text Editor → Code Cleanup** (**Сервис → Параметры → Текстовый редактор → Очистка кода**) → **Run Code Cleanup profile on Save** (**Запускать профиль очистки кода при сохранении**); в профиле очистки должно быть действие **Format document** (**Форматировать документ**).

**Кодировка файлов.** Все файлы курса — в кодировке UTF-8, компилятор MSVC запускается с флагом `/utf-8`. Если в файле с русскими комментариями или строками после сохранения появились «кракозябры» или компилятор пишет предупреждение `C4828` (недопустимый символ), сохраните файл в UTF-8: **File → Save As…** (**Файл → Сохранить как…**) → стрелка справа от кнопки **Save** → **Save with Encoding…** (**Сохранить с кодировкой…**) → **Unicode (UTF-8 without signature) - Codepage 65001**.

## 6. Git в Visual Studio

Команды Git из [WORKFLOW.md](WORKFLOW.md) работают в терминале (раздел 7) без изменений — это самый надёжный способ. Те же действия можно выполнять и мышью, в меню **Git** Visual Studio:

| Действие ([WORKFLOW.md](WORKFLOW.md)) | В Visual Studio |
|---|---|
| Текущая ветка, переход в другую | строка состояния внизу справа — имя ветки; щелчок открывает список веток |
| Создать ветку `lab-NN` (раздел 3) | перейдите в `main` → **Git → New Branch…** (**Git → Создать ветку…**) → имя `lab-01`, **Based on** — `main`, флажок **Checkout branch** отмечен → **Create** |
| Коммит (раздел 3) | окно **Git Changes** (**Изменения Git**; **View → Git Changes**, `Ctrl+0, Ctrl+G`): **+** у файлов, которые входят в коммит, сообщение в поле вверху → **Commit Staged** (**Зафиксировать индексированные**) |
| Отправить ветку на GitHub | в окне **Git Changes** — кнопка **Push** (**Отправить**, стрелка вверх); первая отправка новой ветки сама создаёт её на GitHub |
| Получить изменения из своего репозитория | в окне **Git Changes** — кнопка **Pull** (**Извлечь**, стрелка вниз) |
| Получить новую лабораторную из `upstream` (раздел 1) | в терминале: `git switch main`, `git pull`, `git pull --no-edit upstream main`, `git push` |
| Удалить ветку после слияния | **Git → Manage Branches** (**Git → Управление ветвями**) → правый щелчок по ветке → **Delete** (**Удалить**) |

Получать лабораторные из репозитория преподавателя удобнее командами: кнопка **Pull** в Visual Studio получает изменения только из `origin` — вашего репозитория.

При первой отправке Visual Studio (через Git Credential Manager) откроет окно входа в GitHub — войдите через браузер. Если вы уже выполнили `gh auth login` ([SETUP.md](SETUP.md), раздел 4), вход не понадобится.

Запрос на слияние создаётся и сливается в браузере, на сайте GitHub, — [WORKFLOW.md](WORKFLOW.md), раздел 4.

## 7. Терминал

Встроенный терминал Visual Studio — **View → Terminal** (**Вид → Терминал**), `` Ctrl+` ``. Это **Developer PowerShell**: в нём уже настроены пути к компилятору MSVC, CMake и Ninja Visual Studio, и он открывается в корневой папке репозитория. Команды из [README.md](README.md) («Сборка и запуск в терминале») выполняйте в нём с пресетом `msvc-debug`:
```powershell
cmake --preset msvc-debug                         # настройка проекта → build\msvc-debug
cmake --build --preset msvc-debug                 # сборка всех программ и тестов
.\build\msvc-debug\bin\lab-01-task-02_arithmetic  # запуск программы
ctest --preset msvc-debug -R "lab-03-task-04\."   # тесты задачи
```

В **обычном** PowerShell или командной строке Windows компилятор `cl` не найден — сборка остановится с ошибкой `No CMAKE_CXX_COMPILER could be found`. Для сборки из отдельного окна открывайте из меню «Пуск» **Developer PowerShell for VS 2022** (или **x64 Native Tools Command Prompt for VS 2022**). Для команд Git подходит любой терминал.

## 8. Если что-то не работает

| Сообщение или симптом | Что сделать |
|---|---|
| Нет списка пресетов, нет пункта **Build All**, Visual Studio не видит проект CMake | открыта не корневая папка репозитория: **File → Open → Folder…** → `cpp-labs`. Или не установлен компонент **C++ CMake tools for Windows** (раздел 1) |
| `CMake 3.24 or higher is required` | обновите Visual Studio: **Visual Studio Installer → Update** |
| Выбран пресет **Debug (GCC/Clang)**: `No CMAKE_CXX_COMPILER could be found` или не найден `g++` | выберите в списке **Configuration** пресет **Debug (MSVC)** |
| `clang-tidy не найден — сборка без проверки стиля` | раздел 5 |
| В обозревателе тестов нет тестов | соберите проект (`Ctrl+Shift+B`); если не помогло — **Project → Delete Cache and Reconfigure** и снова сборка |
| Ошибки `#include` подчёркнуты в редакторе, хотя проект собирается | **Project → Delete Cache and Reconfigure** |
| Ошибка `LNK1168: cannot open … .exe for writing` | программа ещё запущена — закройте её окно консоли и соберите снова |
| Русские буквы в окне программы выводятся «кракозябрами» | консоль Windows по умолчанию работает не в UTF-8. Выводите текст латиницей или включите UTF-8 для консоли: **Параметры → Время и язык → Язык и регион → Административные языковые параметры → Изменить язык системы…** → флажок **Бета-версия: использовать Юникод (UTF-8) для поддержки языка во всём мире**, затем перезагрузка |
| `The current CMakeCache.txt directory … is different` или `Does not match the generator used previously` | проект собирался в другом окружении: удалите папку `build\msvc-debug` и откройте проект снова |
| Хотите решить задачу модулем C++20 | MSVC модули собирает, но clang-tidy их не проверяет — CMake выведет предупреждение ([WORKFLOW.md](WORKFLOW.md), «По желанию: решение в виде модуля C++20») |
